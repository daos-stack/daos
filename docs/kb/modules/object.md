# Object layer (`src/object`)

Overview: [src/object/README.md](../../../src/object/README.md). Client-side header:
`src/include/daos/object.h`; server-side: `src/include/daos_srv/object.h`; RPC wire formats and
opcode list: `src/object/obj_rpc.h` (see [generated/rpcs.md](../generated/rpcs.md#object)).

## Purpose

Implements the object API (`daos_obj_*`) on both sides. The client computes the object layout
(placement), splits I/O per redundancy group / shard, handles EC encoding, checksums and retries,
and sends CaRT RPCs to targets. The server validates the request (handles, pool map version,
capabilities), wraps the modification in a DTX, forwards to the other shards, and executes against
VOS/bio. Also hosts EC aggregation, migration (used by rebuild), enumeration, collective punch/query
and distributed-transaction (CPD) RPCs.

## Entry points

- Client API wrappers in `src/client/api/object.c` (`daos_obj_open()`, `daos_obj_update()`,
  `daos_obj_fetch()`) create a task and schedule `dc_obj_*_task()` from `src/object/cli_obj.c`.
- Placement: `src/placement/pl_map.c::pl_obj_place` produces `daos_obj_layout`/shard targets.
- Server handlers: full list in [generated/rpcs.md](../generated/rpcs.md#object).

## Key structures

- Client: `src/object/obj_internal.h::dc_object`, `src/object/obj_internal.h::obj_auxi_args`
  (per-task state, retry flags), `src/object/obj_ec.h::obj_reasb_req` (EC reassembly).
- Wire: `struct obj_rw_in` / `obj_rw_out`, generated by `CRT_RPC_DECLARE(obj_rw, ...)` from the
  field list `src/object/obj_rpc.h::DAOS_ISEQ_OBJ_RW` (`orw_map_ver`, `orw_dti`, `orw_bulks`, ...).
  All RPC structs follow this `CRT_RPC_DECLARE` pattern, so grep for the `DAOS_ISEQ_*` macro.
- Server: `src/object/obj_internal.h::obj_io_context` (pool/container child, map version, object class).
- Task args: `src/include/daos_task.h::daos_obj_rw_t`.

## Threading

- Client: everything is an asynchronous TSE task (`src/common/tse.c`); completion callbacks
  (`src/object/cli_obj.c::obj_comp_cb`) decide retry vs. finish.
- Server: I/O handlers run as ULTs on the target's main (`DSS_XS_VOS`) xstream; leader forwarding
  is offloaded with `dss_chore_register()` (via `dtx_leader_exec_ops()`); EC aggregation and
  migration run as background ULTs.

## Invariants and gotchas

- Every I/O RPC carries the client's pool map version. The server (`obj_ioc_begin()`) rejects
  stale requests with `-DER_STALE`; the client refreshes the pool map and retries
  (`src/object/cli_obj.c::obj_retry_cb`). Don't swallow `-DER_STALE`.
- `-DER_INPROGRESS` / `-DER_TX_RESTART` / `-DER_AGAIN` are retryable conditions handled by the
  client; see [modules/dtx.md](dtx.md).
- The dkey hash selects the redundancy group; all akeys under a dkey are co-located.
- EC: parity shards for a stripe live on dedicated shards; parity extents are marked with
  `src/include/daos/object.h::DAOS_EC_PARITY_BIT`. Partial-stripe writes are replicated and later
  folded into parity by EC aggregation.
- Protocol change -> bump `DAOS_OBJ_VERSION` and keep older formats (note the `ver == 9 ?` cases
  in `OBJ_PROTO_CLI_RPC_LIST`).
